Related variants retain their source independence group; older provisional15 rows, their labels/versions and runtime_driver=pending stay intact. Eligible new recipes initially use public_sequence; subprocess_barrier and controlled_order recipes remain explicit not_started unless their concrete separately registered implementation/dependencies exist. No fake barrier, hard timeout, natural crash frequency, calibration or four600-second drill claim.

The read-only design's DriverManifest and RunnerReceipt fields are the exact base surfaces. Implement frozen/slotted local dataclasses with exact canonical byte/tuple/string/int/finite numeric storage and detached accessors; no mutable aliases or model_copy validation bypass. DriverManifest canonical representation version is runtime-driver-v1 with exact fields: driver_id, obligation, variant, case_id, independence_group, case_bytes_hash, scenario_hash, driver_code_hash, candidate_manifest_hash, profile_name, profile_hash, process_hash, policy_hash, expectation_version, expectation_hash, execution_kind, dependency_ids. obligation is one R01..R15; execution_kind public_sequence|subprocess_barrier|controlled_order. All identity hashes are strict lowercase SHA256; bounded nonempty exact strings/tuples, unique dependency IDs. Reject duplicate/missing/extra JSON, nonfinite/overflow/deep/invalidUTF8/noncanonical content rather than repairing or truncating.

RunnerReceipt stores exact manifest_bytes/hash, ordinal0..255, repetition0..15, status completed|failed|invalid_output|no_output|not_started, dependency_limits, ordered raw_event_bytes, raw_output_bytes/hash or None, score_projection_bytes or None, projection_version, bounded error_bytes or None, process_exit or None, barrier_receipt_bytes, elapsed_seconds or None and source_pre_manifest_bytes/source_post_manifest_bytes or None. ## Reference-free registered execution

Add frozen RegisteredDriver and DriverRegistry(registrations:tuple[RegisteredDriver,...]) with resolve(manifest). Each trusted registration pins complete immutable input_sequence_bytes, scenario_bytes, candidate_manifest_bytes, profile/process/policy bytes, driver_code_bytes, dependency evidence and finite limits plus an explicit callable. Verify content joins against manifest before execution and reject duplicate driver/variant registrations/unknown or mismatched manifests. These hashes bind bytes only, not authenticity/permission. Do not select callbacks/imports/routes/profile files/source mutations from case bodies or labels.

The callable receives only a frozen reference-free DriverInput containing exact input_sequence_bytes/scenario_bytes, case_id/obligation/variant and candidate/profile/process/policy identities plus a bounded event sink/control object. It does NOT receive expectation bytes/hash/version, grading predicates, reference labels, rubric, expected outcomes, full DriverManifest or future feedback. Host registration may retain the grading companion separately, never forward it to source/runtime callbacks. The event sink accepts only actual capture bytes from the trusted public driver, enforces count/byte/cutoff, and exposes no expected values. Trusted test/control callables are labeled as such, not proof of arbitrary-hostile-Python isolation.

run_driver(registry,manifest,input_sequence_bytes,*,ordinal,repetition)->RunnerReceipt revalidates strict captured manifest/registration/input hashes and dependency eligibility before callback; no callback/source entry for missing/unknown/mismatched dependencies. Preserve actual callback Exception as failed with bounded safe error evidence; do not swallow BaseException/process exit/interrupt as success. Keep invalid returned output, absent output and unavailable infrastructure distinct. Retain source PRE/POST actual candidate file hashes through a trusted fixed source snapshot accessor or exact host-supplied immutable candidate snapshot; never infer PREPOST from output. A synthetic immutable byte snapshot is explicitly fixture-only, not live source hold. Actual public-runtime tests use a fixed concrete source/data list and filesystem hashes; drift yields unqualified failed evidence.

Callable output uses a strict captured companion with ordered raw_event_bytes and optional raw_output_bytes, optional separately typed effect-only score projection and observed source snapshots; it is not an arbitrary successful receipt supplied by the case. Complete capture validates canonical byte/hash joins and no missing events. Existing effect-only ObservedOutput may be a projection for compatible cases, but cannot certify stop/order/epoch/debt/version obligations. No production object mutation/SQL/private host handles, old unittest method invocation or granted scope copied from expected answers.

## Declarative grading

assess_driver(receipt,expectation_bytes)->DriverAssessment performs no runtime/provider/driver callback entry and invents no missing trace/effect. Exact independently frozen expectation_version/hash must join manifest. Strict expectation JSON version driver-expectation-v1 has only version, expectation_version and predicates. Each predicate has unique id, event_tag, field_path (tuple/list of bounded string/int path components), operation equals|count_equals and expected (strict bounded canonical JSON). Every captured event is a canonical object with an exact nonempty event_tag and independently captured data. equals requires exactly one matching observed public event and an existing field path; count_equals counts explicit matching events and its expected is an exact nonnegative integer (its field_path must be empty). No matching event is insufficient even when the requested count is zero; verified physical zero needs an explicit captured counter event and equals0, not absent logs. Missing/ambiguous trace/path is insufficient, not absent-effect success. Invalid/ref/hash output remains ungraded. Report passed|failed|insufficient|ungraded and per-predicate outcomes with actual raw references, no generic percent/implicit readiness. Predicate traversal max16, predicates max64, no arbitrary code/import/query/tool/LLM or substring judging.

Known-good/bad/insufficient same-byte controls must separate, repeated/swapped predicate presentation preserves their IDs/factual outcomes, and the grader never executes the system. These tests establish local deterministic grader mechanics only, not calibrated LLM judges/statistical power/production quality. Trace/source groups remain explicit; three group recipes cannot establish fifteen independent obligations.
