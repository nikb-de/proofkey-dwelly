# J06 — trusted installed-case provisioning

## Why

The installed runtime passes its two fixed demonstrations, but an integrating engineer still needs test-only construction code to prepare a different case for the registered path. The next milestone is a genuinely new reschedule or whole-order refusal/return through shipped library and CLI code, with unchanged source and verifiable outcomes.

## What Changes

- Add a small, explicitly synthetic, two-stage preparation API: prepare a fresh case release, then construct launch configuration using a separately supplied review grant and transport resolver.
- Permit `CliConfiguration` to carry one exact existing `LocalAdmissionCompositionV1`; forward it to the existing dispatcher. No default launch behavior changes.
- Provide two independently authored examples, changing business arguments and source facts as well as identity labels. Exercise both through installed library and trusted CLI bootstrap.
- Keep source snapshots, private artifact preparation, authority, runtime execution and public receipts distinct.
- Add negative tests and retained installed evidence; preserve all existing fixed examples and denial contracts.

This proposal is a draft for written approval. It does not authorize implementation, provider calls or broader admission/control changes. No breaking wire or CLI syntax change is proposed.

## Capabilities

### New Capabilities

- `trusted-replay-case-provisioning`: finite synthetic preparation and explicitly authorized installed CLI/library launch of a nonbuiltin business case, with isolated state and evidence-bound acceptance.

### Modified Capabilities

None. Installed resource guarantees and the existing admission protocol remain unchanged. General release verification, registered controls, process adaptation and meaningful media processing remain separate work.

## Impact

Expected production changes are one new `runtime/src/proofkey/synthetic_provisioning.py` module, the optional composition field/validation in `bootstrap.py`, and forwarding in `cli.py`. Focused tests and a separately supplied example pack are added. No change is intended in host admission, engine, gateway, journal, source semantics, policy or executable pin allowlists. No new dependency or network access is needed.

This milestone proves a reusable **trusted Python integration hook** using the installed CLI implementation. It does not claim a generic configuration-file launcher, unfamiliar-engineer usability, a ten-minute adaptation result, or connection to a native logistics system.
