# Canonical hackathon submission packaging

## Why
The existing main branch contains a working local product and development evidence but mixes current run instructions with obsolete planning artifacts. The supplied hackathon rules require an independently reproducible public repository, transparent per-case results, an in-repository short video and explicit licensing and launch status.

## What Changes
- Refresh the eight-section README and A–G submission checklist without claiming unsupported outcomes.
- Publish the supplied final video with duration, digest and provenance.
- Package retained development records without correcting failed outputs or asserting official challenge provenance.
- Remove the reviewed obsolete files from the current tracked tree while retaining operational dependencies and real evaluation evidence.

## Impact
No production decision policy, provider selection, source case or operational adapter is changed. Missing official results and launch URLs remain explicit.
