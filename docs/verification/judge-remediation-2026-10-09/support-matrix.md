## Read the support levels correctly

J06 adds an opt-in trusted Python hook: `SyntheticCaseReleaseSpecV1`,
`prepare_synthetic_release` and `configure_registered_cli`. The application
separately supplies a review resolver and transport resolver, then explicitly
selects its prepared release through the existing library or `cli.main` API.
Candidate `80e0d6f` passed four fresh installed new-case positions and seven
negative positions. Scoped final-fix re-review and frozen regression passed:
1,769 tests run, 1,768 passed, one environment-dependent macOS alias skip,
zero failures/errors; the skipped test separately passed with inherited macOS
TMPDIR. Strict prearchive validation passed; [J06 is closed and archived](../../../openspec/changes/archive/2026-10-09-trusted-replay-case-provisioning/tasks.md) for this bounded hook. The [living specification](../../../openspec/specs/trusted-replay-case-provisioning/spec.md) contains its six requirements.
See [J06 verification](../2026-10-09-trusted-replay-cases.md) for all five
attempts (16/20 positive complete-check passes, 34/35 negatives), exact target,
hashes, return-initiation boundary and remaining
gates. No public authority flag, manifest launcher, native connector or API
composition selector was added.

- **Builtin public path:** `ProfileRegistry.builtin` + the ordinary `RuntimeFactory`, used by default CLI and explicitly constructed library/API wrappers. It has two fixed synthetic replay registrations, `host-window-replay-v1` and `host-goods-replay-v1`, with exact kind/fingerprint commitments (`runtime/src/proofkey/host.py:112-124,533-536`).
- **Registered admission path:** explicit library construction of `LocalAdmissionCompositionV1` and `HostDispatcher(..., admission_composition=...)`, using `RuntimeFactory.create_registered`. It adds durable claim/route sealing and code/profile/resource/review checks. It is **not** selected by default CLI/API construction (`host.py:256-280`; `cli.py:190-191`; `api.py:194-198`).
- **Core engine or trusted custom composition:** additional code exists below the public launch boundary and can be exercised with purpose-built trusted fixtures. Existence of that code does not make a feature available from builtin commands.
- **Live integration:** no native logistics service connection is established by these source paths. Builtin worlds and the registered bridge use `SimulatedWorld`; all six adapters below are simulated. Optional ASGI is a transport wrapper, not a native provider connector.

## Commands by entrypoint

CLI syntax is `python -m proofkey.cli [--release ID] [--credential-ref REF] COMMAND`. The installed `proofkey` script is declared in `runtime/pyproject.toml`; the initial discovery pass did not verify clean installation, while the addendum above supplies subsequent evidence for the specific target and cases. CLI flags may also follow the subcommand (`cli.py:32-47`).

The API is created explicitly with `create_app(...)`, trusted factory/resolver/registry/limits/clock and existing output/inventory parents (`api.py:460-490`). It exposes only POST `/v1/commands`, POST `/v1/batch`, GET `/v1/profile` (`579-589`). Each instance selects one release. It requires exactly one bounded `x-proofkey-proof` header mapped by the configured resolver to an opaque handle **before reading the body** (`534-550`). Localhost and header text alone are not authentication. There is no public polling, shutdown, docs or OpenAPI route (`api.py:501`; `test_api_boundary.py:325-328`). `serve_loopback` accepts only a literal loopback address and valid port (`594-603`). This is source-described support, not a currently running service.

## Six provider-neutral logistics ports

All six are present in `AdapterBundle` (`ports.py:48-55`). `SimulatedWorld.bundle` wires six local adapter instances (`adapters/world.py:205-210`). These adapters call the simulated world's read/dispatch methods; they are not six external connections. A workflow need not call every port, and the two positive examples do not establish complete six-port coverage.

| Port | Contract methods | What it can mean in current synthetic code | Public/default and live caveat |
|---|---|---|---|
| Case | `read_case`, `read_principal` (`ports.py:9-11`) | Read designated case/identity/consent and principal facts. Gateway authenticates before binding and scopes source reads. | Used as authority input, never customer consent inferred from request prose. No native case-system connector demonstrated. |
| Delivery | `read_delivery`, `read_refusal`, `register_goods_refusal`, `register_service_refusal` (`14-18`) | Read lifecycle; conditionally register whole goods or completed-service refusal. | Goods is a builtin positive; service remains below fixed public registration. Refusal does not itself create a return/refund. |
| Scheduling | `list_permitted_slots`, `read_schedule`, `reschedule` (`21-24`) | Select within permitted source slots, conditionally write schedule and verify original effect. | Builtin window positive; exact-slot process not builtin. No calendar/delivery-provider API connected. |
| Returns | `read_return_policy`, `read_return`, `create_return` (`27-30`) | Verify policy/destination/quantity and create a distinct return effect after verified goods refusal. | Builtin goods positive. Stages `initiated` and `received` are different (`world.py:512-515`); receipt cannot be inferred from initiation. |
| Messaging | `read_message`, `send_clarification`, `send_status` (`33-36`) | Send/read scoped simulated communications, with recipient and permission checks (`adapters/messaging.py:11-18`; `world.py:522-529`). | No public positive messaging observation established in this inspection; no real SMS/email/chat transport. Syntax does not create a valid wait. |
| Operator | `read_receipt`, `read_resume`, `read_owner`, `enqueue_handoff`, `transfer_owner` (`39-45`) | Queue/read simulated operator handoff; separate profile/service can support ownership transfer (`adapters/operator.py:11-25`). | Builtin business examples are not operator integration proof. Handoff queue acknowledgement is pending, not accepted ownership. Public transfer unavailable. |

The world records conditional idempotent effects and original readback separately (`world.py:406-447,730-760`). `DispatchResult` is an acknowledgement; verification uses original action identity, fingerprint, postconditions, stage and source evidence (`verifier.py:12-71`). A transport success must not be presented as a verified outcome.

## Proposed short engineer onboarding

1. Read the [current installed-target guide](../../../runtime/README.md#installed-target) or the source-checkout recipe (discovery reference: `runtime/README.md:7-36`), then select **one of the two fixed replay examples**. Python >=3.11 and exact core dependency versions are declared in `runtime/pyproject.toml`; optional API and API-test dependencies are separate. Only CPython 3.12.14 / macOS arm64 has the installed evidence above; the version declarations do not qualify other environments.
2. Use a new temporary launch directory for each example, preserve the absolute runtime source path, and keep the exact documented request and replay dates. The default CLI creates `.proofkey/resources`, `.proofkey/inventories` and `.proofkey/runs` under its working directory. Do not point it at an unrelated existing state directory or edit fixture facts to make an outcome succeed.
3. For an application, construct trusted clock/resolver/registry/limits and one creator-owned `HostDispatcher`; use `run_command` or `run_batch` with explicit original execution and publication bounds (`batch.py:22-38,234-235,341-342`). Close the owner and preserve its receipt. API users must call `create_app` with the same trusted inputs plus a real transport-proof mapping; no global ASGI app is supplied.
4. Use the registered admission bridge only when independently supplying its exact executable/profile/resource binding and synthetic review resolver. It requires a fresh isolated root and dedicated control stores. The [trusted Python example](../../../runtime/examples/registered_case_bootstrap.py) prepares independent structured window/goods cases within the fixed family; [J06 evidence](../2026-10-09-trusted-replay-cases.md) records the installed results. Do not try to enable it through command JSON or copy a stored claim as proof.
5. Inspect the returned result, export and shutdown independently. For a positive window expect verified `reschedule`; for goods expect both verified refusal and verified `create_return`. Verify actual exported file hashes and final manifest joins using the existing recipe at `runtime/DEMO.md:119-124`. A zero process exit or HTTP 200 alone is insufficient.

This is onboarding to the currently bounded replay harness, not onboarding for arbitrary production workloads. Broader trusted registration, registered controls, service cases, semantic media, current live authentication and native adapters remain separate implementation/qualification work.

## Diagnose denial, pending and unknown without unsafe retries

| Observation | Meaning / first check | Safe next step and boundary |
|---|---|---|
| CLI `invalid_usage` / exit 64 | Closed syntax rejected (`cli.py:147-151`). | Compare command/required flags with `cli.py:32-47`; do not assume `--help` is implemented by this custom parser. |
| CLI `invalid_input` / exit 2 | Release/credential/input load or canonical request parsing rejected (`cli.py:176-183`). | Check selected registered ID, exact builtin input, JSON duplicates/types and credential reference. Do not put principal authority into the body. |
| `denied` / `scope_denied` | A trust, source, profile, request, generation or time gate rejected. Public denial intentionally exposes only correlation and generic reason (`contracts.py:735-755`). | Use private trusted inventory and configuration evidence; verify exact selected release, resource ownership, original binding, source access and time. Do not “fix” by disabling the guard or revealing protected state. |
| `unavailable` on transfer, direct host batch or completed recover | Often an intentional unsupported command/path, not transport failure (`host.py:635-638`; `engine.py:356-357`). | Use the wrapper batch API where intended; inspect the support matrix before retrying. Completed historical replay is a distinct operation from recovery. |
| `pending_claim` during registered open/run | Prepared or sealed claim survived without observed admission, potentially after real effects (`host_admission.py:469-471,606,662`). | Retain original files/debt; current implementation has no registered recovery path. Do not delete control files, reinitialize root or switch to legacy factory. Escalate with hashes and private inventories. |
| `started_pending`, wrapper pending or incomplete shutdown | Work entered, but waiting ended before final completion; queued cancellation and entered work have different semantics (`host.py:591-621`; `api.py:242-251`). | Preserve command IDs/inventories. Do not reissue a potentially executed effect; public API has no polling endpoint. A timeout is not cancellation or proof of no effect. |
| `wait_status: pending` | Process is waiting, or paused at an unknown outcome (`engine.py:754`). | Inspect actual wait/question and required actor through authorized state. Only an authentic scoped reply may continue; registered route currently cannot accept one. |
| Per-effect `outcome_unknown` | Entry occurred without a conclusive original readback (`engine.py:742-746`). | Reconcile the original action/key under the original process and budget where supported. Absence from an eventual read is not proven nonexecution. Never create a fresh key just to retry. |
| Handoff `pending` with verified queue effect | Queueing was verified; operator acceptance was not (`engine.py:747-749`). | Retain pending disposition. Do not claim ownership transfer, external handling or business resolution. |
| Refusal verified, return rejected/unknown | Independent partial outcome is expected. | Preserve the verified refusal and diagnose/reconcile only the original return. Do not erase one effect to make the case look uniformly failed/successful. |
| Publication/export failure or CLI exit 4 / API 503 | Operational effect and output durability may diverge. See `cli.py:95-138` and `api.py:355-411`. | Preserve source/journal and available output references; check actual bytes/owner state. Do not rerun the business operation solely to regenerate an export. |
| New CLI process denies retained work | Default `SyntheticReplayClock` restarts its epoch (`clock.py:34-46`), and current source/saved times may not line up. Test source preserves this denial (`test_cli_parity.py:194-223`). | Treat positive restart as unqualified; do not renew consent, move time backward, reset deadlines or clear state. |

CLI exit mapping is 0 coordinated result/inspection, 2 denial/unavailable/input, 3 deadline/pending, 4 infrastructure/publication/owner issue, 64 usage (`cli.py:95-151`); higher-level shutdown may override a prior result. API status is selected from the complete receipt with publication failure outranking pending (`api.py:355-411`). HTTP status, business result, each effect, publication and owner shutdown must be read separately.

## Evidence limits and open documentation gaps

- Source tests define positive CLI/API/library parity for **two fixed synthetic examples** (`test_cli_parity.py:122`; `test_api_parity.py:18`). Those source references are not fresh passes; clean installation is evidenced separately by the addendum's receipts. Neither establishes other platforms, native providers or six-port completeness.
- Source tests cover core service/handoff, waits, durable stop and subprocess crashes. The positive scope varies by fixture, profile, clock and entrypoint; a single global “supports recovery” label would overstate it.
- Registered selection and bounded window/goods provisioning are available through trusted Python library/CLI configuration. Public authority flags, an API composition selector, persistent manifest launcher, recover/reply/stop and safe classification/recovery of interrupted claims remain unavailable/unestablished. Exact code compatibility and resource identity remain deliberately restrictive.
- A frozen end-to-end receipt set for service refusal, real retained reply/stop, all six port uses and the four declared crash cases remains a distinct evidence deliverable. Do not omit denied, failed, missing or partial cases from its denominator.
- Native authority/conditional-write/readback semantics, operator identity, actual model/transcription calls, actual human review, package/platform reproduction beyond the recorded installed target and timed drill outcomes remain unestablished here.
- The final public README should adopt a shortened version of these matrices only after root review. This draft does not change existing README, tests, runtime behavior or OpenSpec contracts.
