# Серверная библиотека JSON

Этот документ описывает прежний режим файлового архива и резервное хранение. Текущий режим чтения из репозитория включается через `LIBRARY_SOURCE=github`: см. [GITHUB.md](GITHUB.md).

В режиме файлового архива библиотека может быть открыта всем посетителям. Загрузка файла и применение JSON из редактора автоматически сохраняют документ на сервере. Переключатель «Сохранённые кейсы» показывает сохранённые версии; «Обновить список» подтягивает загрузки других посетителей.

Одинаковые данные имеют один SHA-256 ID независимо от форматирования и порядка ключей. Изменённые данные создают новую запись; старые версии не перезаписываются. В URL сохраняется `#saved=<id>`, поэтому выбранный кейс можно открыть по ссылке. Выбранный шаг при открытии начинается со старта.

При ошибке записи JSON остаётся во вкладке, интерфейс показывает «Не сохранён на сервере» и кнопку повторной попытки. Сообщение об успехе появляется только после ответа сервера. Новые загрузки не видны другим посетителям до успешного сохранения.

## Локальный запуск

Из корня репозитория, Node.js 22+:

```sh
LIBRARY_ACCESS=public \
CASES_DIR="$PWD/.case-library" \
STATIC_DIR="$PWD/case-state-widget" \
SEED_DIR="$PWD/case-state-widget" \
PORT=8080 \
node case-state-widget/server/server.mjs
```

Откройте http://127.0.0.1:8080. Выберите свободный порт при необходимости. По умолчанию сервер слушает все интерфейсы; для доступа только с этого компьютера добавьте `HOST=127.0.0.1`.

`SEED_DIR` добавляет обычный 002 и негативный 002-N4 при запуске. Повторный запуск не дублирует неизменённые данные. Это подготовленные примеры; ранее открытые произвольные файлы из памяти закрытых вкладок сервер восстановить не может — их нужно загрузить заново.

## Хранилище

Каждая версия записана отдельным файлом `<sha256>.json` вне каталога статических ресурсов. Файл содержит метаданные и исходный документ. Запись проходит через временный файл и атомарное переименование; операции сохранения внутри одного процесса последовательны.

Ограничения: 5 МБ на документ, 1000 шагов, до 1000 записей и 250 МБ суммарного содержимого архива. При заполнении сервер отклоняет новую запись, сохраняя существующие. Удаление и редактирование существующих записей через API не предусмотрены.

В Fly приложение `dwelly-logistics-atlas` использует постоянный том `case_library`, смонтированный в `/data`; JSON лежат в `/data/cases`. Данные переживают перезапуск процесса и замену образа при сохранении того же тома. Не удаляйте том при обновлении. Один том обслуживается одним экземпляром приложения; это не распределённое хранилище.

Резервную копию делайте из каталога `CASES_DIR` или средствами снимков тома. Постоянный том сам по себе не является независимой резервной копией.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `PORT` | Порт, по умолчанию 8080 |
| `HOST` | Адрес привязки, по умолчанию `0.0.0.0` |
| `CASES_DIR` | Постоянное хранилище, по умолчанию `/data/cases` |
| `STATIC_DIR` | Каталог сайта; хранить JSON архива внутри него нельзя |
| `SEED_DIR` | Необязательный каталог двух начальных примеров |
| `LIBRARY_ACCESS` | `public` — открытый архив; `team` — доступ по ключу, значение по умолчанию |
| `LIBRARY_TOKEN` | Для `team`: ключ длиной минимум 24 символа, задаётся вне исходников |

В режиме `team` API требует Bearer-токен; оболочка показывает поле ключа и хранит его в `sessionStorage` вкладки. На текущем опубликованном сайте выбран режим `public`, поле ключа не показывается.

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/config` | Режим доступа и максимальный размер документа |
| GET | `/api/cases` | `{ cases: [{ id, filename, title, case_id, step_count, created_at }] }` |
| GET | `/api/cases/<id>` | Метаданные и `data` — полный JSON |
| POST | `/api/cases` | Принимает `{ filename, data }`; возвращает `{ entry, created }` |
| GET | `/healthz` | Проверка доступности процесса |

POST требует `Content-Type: application/json`. Данные проверяет тот же `validateCase()`, что использует виджет. Ошибки формата возвращают 400/422, размера — 413, вместимости — 507. Новый документ возвращает 201; существующий — 200. Запросы POST с чужим Origin отклоняются. Доступ по ID не скрывает документ в публичном режиме: библиотека намеренно открыта.

## Docker

```sh
docker build -t case-state-widget case-state-widget
docker volume create case-library
docker run --rm -p 8080:8080 \
  -e LIBRARY_ACCESS=public \
  -v case-library:/data case-state-widget
```

Статический запуск через Python по-прежнему возможен: в этом режиме сохранения на сервер нет и интерфейс сообщает об этом явно.

## Проверки

```sh
npm --prefix case-state-widget test
```

Серверные тесты проверяют сохранение после перезапуска, точное чтение JSON, дедупликацию, отдельные версии, валидацию, предел вместимости, Origin и доступ по ключу. Интерфейс дополнительно проверен загрузкой нового файла, сменой кейса и перезагрузкой страницы.
