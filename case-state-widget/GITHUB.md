# Каталог из GitHub и предложения через PR

Источник виджета: репозиторий **nikb-de/proofkey-dwelly**, ветка **main**, папка **case-state-widget/cases/**.

[Открыть папку](https://github.com/nikb-de/proofkey-dwelly/tree/main/case-state-widget/cases). Правила для автора разметки — [cases/README.md](cases/README.md).

## Как новые кейсы появляются на сайте

1. Автор добавляет `<id>.json` прямо в `case-state-widget/cases/` и публикует в `main`.
2. Виджет получает список файлов через серверный GitHub API. Статический список и передеплой не нужны.
3. Новый кейс появляется по кнопке «Обновить» в каталоге «Все кейсы» или при периодическом обновлении открытой вкладки раз в минуту.
4. При выборе читается JSON соответствующего файла из `main` и проверяется `validateCase()`.

Каталог кешируется на сервере на 30 секунд; кнопка обновления обходит этот кеш. Список получает только имена и SHA файлов, а содержимое — только при выборе кейса. До первого чтения отображается ID; после чтения — заголовок и число шагов из JSON.

В адресе страницы используется `#saved=002` или `#saved=002-N4`. Под строкой загрузки показаны точный путь файла и сокращённый SHA его содержимого. Обновление списка не перезаписывает открытый JSON или локальные правки.

Поддерживаются JSON непосредственно в папке; вложенные папки не обходятся. Имена: латинские буквы, цифры, `-`, `_`, до 100 символов, первый символ — буква или цифра. GitHub Contents API ограничивает каталог: при 1000 файлах потребуется разделение или другой способ перечисления.

## Доступ сервера

Для Fly-приложения `dwelly-logistics-atlas`:

- `LIBRARY_SOURCE=github` включает интеграцию.
- `GITHUB_READ_TOKEN` задаётся через Fly Secrets и должен иметь доступ чтения Contents к `nikb-de/proofkey-dwelly`. Выдача токена или GitHub App должна соответствовать доступу владельца и политике репозитория.
- Для публичного репозитория чтение возможно без токена, но действует меньший лимит GitHub API.
- Токен чтения остаётся на сервере; его нет в JavaScript страницы, URL, JSON кейса и логах приложения.

При недоступности GitHub во время подключения сохраняется прежний серверный архив, а интерфейс явно сообщает причину. Это временный резервный источник, а не выдача старых данных за содержимое GitHub. После добавления секрета Fly перезапускает приложение с новым окружением; каталог переключается на GitHub. Вкладка проверяет готовность подключения раз в минуту; также можно перезагрузить её.

Новые загруженные файлы в режиме GitHub остаются локальными черновиками до PR. Автоматическая запись непосредственно в `main` отсутствует. Старые JSON на томе `/data` не удаляются.

## Кнопка «Создать PR»

Откройте кейс, отредактируйте JSON и нажмите «Применить JSON». Затем «Создать PR» откроет форму:

- ID кейса задаёт единственный файл `case-state-widget/cases/<id>.json`.
- Ваш GitHub-токен должен позволять создавать ветки, менять Contents и создавать Pull requests в этом репозитории. Токен сервера, используемый только для чтения, для записи не используется.
- Нажатие «Создать черновик PR» создаёт ветку `case-widget/<request-id>`, коммит одного JSON и draft pull request в `main`.
- После создания отображается ссылка на PR. Изменения станут частью каталога после его слияния человеком.

Токен пользователя передаётся серверу по HTTPS для выполнения запросов к GitHub. Он не сохраняется на диске, в `sessionStorage` или в кейсе; после успешного запроса поле очищается. Не вводите токен на локальном HTTP-сервере, доступном посторонним; локальный тест привязывайте к `127.0.0.1`.

Если исходный файл изменился в `main`, сервер отклоняет предложение: загрузите актуальную версию и перенесите свои правки. Неизменённый JSON не создаёт PR. Повторная попытка того же запроса возвращает существующий PR; после сетевого сбоя сохраняйте тот же открытый черновик для повтора.

Для нового файла выберите свободный ID. Загрузка произвольного JSON не даёт права перезаписать существующий файл: для изменения существующего кейса сначала откройте его из каталога, чтобы получить актуальный SHA.

## Локальная проверка

Из корня репозитория, с токеном в окружении:

```sh
LIBRARY_SOURCE=github LIBRARY_ACCESS=public \
CASES_DIR="$PWD/.case-library" STATIC_DIR="$PWD/case-state-widget" \
HOST=127.0.0.1 PORT=8080 \
node case-state-widget/server/server.mjs
```

`GITHUB_READ_TOKEN` задайте вне исходников. Саму папку `cases` этот сервер не читает с локального диска: в данном режиме данные приходят через GitHub API.

```sh
npm --prefix case-state-widget test
```

Проверки покрывают чтение каталога, конфликт исходной версии, отсутствие изменений, ограничение пути, создание draft PR в отдельной ветке и повтор запроса. Запросы записи в тестах подменены: тестовые PR в репозитории не создаются. Чтение настоящего приватного репозитория и переключение кейсов проверяются отдельно.
