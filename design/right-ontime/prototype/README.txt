START HERE
Extract the complete folder and open index.html. Team and customer interfaces
run directly from local files. No installation, server or internet is needed.
All actions and provider responses are explicitly simulated.

CURRENT DESIGN
The latest approved Forward Fold lockup uses the tighter 75-unit wordmark origin.
The original symbol is unchanged. Exact delivered vectors are included. Right onTime
uses the selected casing. Forest #1D3E23, paper #F3EBDD, restrained brass
#BEA36A, canvas #F9F8F4 and the supplied semantic tokens apply across both roles.
Local Manrope headings and Inter body/controls are bundled with OFL licences.
UI, demo content, code comments, accessibility labels and handoff are English.
This is a brand-only successor to the repaired v4. Its simulator version and
state model remain v4. Earlier versions remain separate records.

WHAT WAS REPAIRED
1. Original operation types survive interruption and reconciliation, including
   refusal. Stop is retained when a late confirmed result arrives.
2. Operator clarification has a customer answer and queue-return path. Decisions
   validate the current revision/stage. Invalid decisions remain visible and
   do not resolve help. Continuation never creates customer consent or books
   automatically. Extra date searches require an explicit scoped allowance
   within the unchanged shared command budget.
3. Team/customer navigation keeps the same case.
4. Collection validates dates against the virtual scenario clock and saves
   exact object/date/time/address/price/revision agreement. Case033 reuses its
   existing consent; its absent address value is explicitly unknown.
5. Waits retain an owner, next check, deadline and finite shared run budgets.
   Exhaustion routes the unresolved obligation to an operator. Customers see
   only a concise support/update status; internal contacts/budgets stay in team.
6. Each request retains its exact body, recipient, channel, intent and consent.
   Responses are attributed and correlated. Wrong/stale evidence is rejected
   visibly; acknowledgements do not imply task completion. Quote and booking
   evidence remain separately inspectable. Blocked sends retain their intent.
7. Simulation preparation has configuration, failed checks, expected/actual
   local rehearsal, ready, explicit enablement, registration and running states.
   Editing settings invalidates checks; an existing run keeps its frozen config.
8. Keyboard focus is restored after task/navigation changes. Field outlines
   have stronger contrast. Layout reflows on mobile and at enlarged rendering.

CLOCKS AND LIMITS
Fixtures use February/March2026 scenario time, not today's wall clock. Each case
starts on its input date. Status checks advance virtual time by five minutes;
the deadline demo event advances past the response deadline. Default shared
limits are six commands and three status checks per run; preparation allows a
bounded range. These are demo policies, not claims about a real carrier SLA.
An exhausted budget retains pending outcomes for human handling, not success.

BOUNDARIES
This is an offline UX prototype, not a production frontend connected to services.
No live AI, carrier API, authentication, real authorisation, external sends,
booking, refund or physical receipt occurs. The role switch is demo navigation.
Browser file-storage rules control persistence; a visible warning appears if
storage is unavailable. Concurrent edits are not transactional. Native date
widgets may follow the viewer's browser locale; supplied text is English.
No actual-user study, full accessibility certification, production security
acceptance or public deployment is included. No Mac exposure claim is made.
The logo similarity observation is not trademark clearance or an exclusivity
claim. The operator authorised local application, not publication.
